# NearbyPass 宣传片 · DECISIONS

> 只读代码得出。所有行号对应 commit `7a7dc11`。

## 项目是什么

macOS 菜单栏 App。用手机 / 手环的 BLE 信号判断你在不在电脑前，然后做三件事：
人在时替你填系统授权弹窗的密码，人回来时自动解锁，人走了自动锁屏。

- 解决的麻烦：离开工位忘了锁屏；回来每次都要敲开机密码；改个系统设置又要输一遍
- 给谁用：一个人、一台 Mac、一部常带在身上的手机或手环（安卓也能用，不依赖 Apple Watch 生态）
- 出处：`README.md:3-9`；三个功能分别是 `AuthDialogHandler.swift`（F1）、`AutoUnlockHandler.swift:1`（F2）、`AutoLockHandler.swift:1`（F3）
- 作者自己的边界声明："不碰系统认证逻辑，不装认证插件，也不用 root"（`README.md:11`）——这句话很有作者气质，片里会用

## 时长：24 秒

- 体量：`Sources/` 26 个 Swift 文件约 6200 行（核心 18 个 ≈ 4000 行 + `Sources/UI/` 8 个 ≈ 2240 行），有 SwiftUI 设置界面、教程、自动更新、签名打包（`build.sh`、`package.sh`）
- 这是**完整的应用**，不是单文件工具，也算不上多模块系统 → 按规则落在 24 秒
- 120 BPM，每小节 2 秒，正好 12 小节 / 48 拍
- 镜头数核过：9 个段落，没超

## 强调色：`#8B5E00` 琥珀

- 代码里本来就有：`Theme.signal`（`Sources/UI/Theme.swift:28`），设计稿里也是 `--signal:#8B5E00`（`docs/redesign/index.html:16`）
- 作者给它定的规矩是"只给会变的东西——阈值、主设备、活数据"（`Theme.swift:27`）。片里照这个规矩用：**只有阈值环、dBm 读数、设备点、高亮代码行是琥珀色**，别的地方一律不用
- 底色和字也全用现成的：纸底 `#E7EAEB`（`Theme.swift:14`）、面板 `#F4F5F6`（`:16`）、墨 `#15191B` / `#4C5359` / `#8A9197`（`:19-21`）
- drop 段转深色时底色就用墨 `#15191B`。`#8B5E00` 压在墨色上对比度不够，所以只在这一段把同一个色相提亮到 `#C99A3E`——不算新加一个颜色
- 吉祥物的 `#DC7958` 是 brief 规定的，属于角色本身，不算强调色
- 刻意不用的：`Theme.away #A4462F`（`Theme.swift:31`）。它和琥珀、吉祥物橙放在一起是三种暖色，太乱。"离开"状态改成墨色空心点来表示
- 没有紫色，也没有渐变

## 节奏性格：中速，丝滑

- 这是 GUI App，主要画面是同心距离场（`Sources/UI/FieldView.swift:1-7`）和设置面板
- 产品本身做的事是"安静地判断、不抖"：迟滞带的存在就是为了不来回跳（`PresenceMonitor.swift:289-291`）。所以动作要靠弹簧连贯过去，不能跳着走
- 起伏：开场密（一拍一个词）→ 核心中速 → 硬核段松一点（代码要给人看清）→ 铺开 + drop 最密（反拍也有动作）→ 最后两拍放慢
- BGM：120 BPM，A 小调五声音阶，numpy 合成，26 秒

## 不展示什么

- **应用内自动更新 / 验签回滚**（`Updater.swift:356-376`）：做得很扎实，但它是发版基础设施，不解决"锁屏解锁"这个麻烦。放进来会把片子拖成功能清单
- **随机广播名、GATT 读真名、手动改名**（`PresenceMonitor.swift:105-169`）：这是修安卓设备边角情况的补丁，讲清楚要两个镜头，观众却得不到核心卖点
- **只显示手机 / 手表 / 手环的过滤**（`DeviceKind.swift:9-45`）、**开机自启**（`LoginItem.swift:7`）、**菜单栏图标可隐藏**、**5 步教程**、**防 App Nap**：都是体验打磨，不是卖点
- **密码存 600 权限文件而不是钥匙串**（`README.md:45`、`KeychainStore.swift:5`）：理由很好（锁屏时没人能点钥匙串授权框），但一拍讲不完，硬塞进去容易被误读成"不安全"，所以砍掉
- **README 里写的默认值 -70**（`README.md:57`）：和代码对不上，代码里是 -60（`Settings.swift:35`）。片里以代码为准，用 -60 / -85
- **测试**：仓库里没有测试文件，`probe/` 下全是 Phase 0 的探针脚本。所以上屏的名字都直接取自源码里的标识符（`evaluateOnLock`、`canAutoUnlock`、`selfLockRequested`、`requireStrongFor`），不用 README 里的说法

## 吉祥物的戏份

NearbyPass 碰的是你的开机密码，但它是个人小工具，作者文风很松（"自动解锁就死那儿了"）。所以吉祥物全程在场，只是收着演：
- 硬核代码段它退到画面右下角，只露半个身子，不抢代码
- drop 段变成反色剪影：纸色身体、墨色眼睛

# 修订 v3（按反馈：去掉代码、放慢）

**1. 不再展示代码。** 原第 25–28 拍的 `evaluateOnLock` 代码镜头整段删掉。"亲手锁屏不会马上解开"这条时间线保留，代码标签全部换成大白话：

| 节点 | 上 | 下 |
|---|---|---|
| 1 | ⌃⌘Q 亲手锁屏 | 手机就在桌上 |
| 2 | 人还在 | 不自动解锁 |
| 3 | 设备先离开 | 记下：人走过 |
| 4 | 再回来 | 这才自动解锁 |

标题："你亲手锁的屏，它不会马上解开"（`README.md:81`）。其它小字也去掉了：`attemptedThisSession = true` 换成"密码错一次就停手"（`README.md:85`），`Log.swift` 和 `canAutoUnlock → true` 直接删掉。画面里只剩 dBm 读数和 `***` 用等宽字体。

**2. 放慢。** 120 BPM → 96 BPM，所有动作慢 1.25 倍。字多的拍再给两拍时间：两句字幕、阈值预测行、授权浮窗、点允许、时间线 4 个节点、铺开 3 个细节、强信号、自动解锁、收尾两拍。时长 24 s → 37.5 s，共 60 拍、15 小节。超过了最初定的 24 秒，因为看清楚比卡时长重要。

画面和音乐用同一张拍表（`film.html` 和 `music.mjs` 里的 `SEG`），所以每个切点、每次点击仍然落在拍上。
